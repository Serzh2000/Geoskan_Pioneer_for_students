# Структура репозитория

Репозиторий устроен вокруг четырёх вопросов: **что запускаем**, **что читаем**, **чему учим**, **что чужое**. Любой каталог верхнего уровня отвечает ровно на один из них.

```
Geoskan-Pioneer-for-students/
├─ simulator/        что запускаем: веб-симулятор дрона
├─ book/             что читаем: учебник (LaTeX)
├─ examples/         чему учим: все примеры, единственный источник
├─ third-party/      чужое, только для чтения
├─ docs/             картинки для README и этот документ
├─ archive/          устаревшее и черновики
└─ .github/          CI
```

## simulator/

Веб-симулятор «Геоскан Пионер»: TypeScript, Vite, Three.js, Monaco, Blockly, сервер примеров на Node.

* `public/` исходники интерфейса, `server.ts` сервер, `tests/` тесты, `tools/` вспомогательные скрипты, `docs/` документы разработчика.
* `examples/`, `examples-python/` **генерируемые копии** каталога `../examples`. Они нужны, чтобы деплой одной папки `simulator/` работал без остального репозитория. Обновляются командой `npm run sync-examples`. Не правьте их руками.
* Запуск: `npm install`, `npm start` (порт 3011). Проверки: `npm run type-check`, `npm test`.

## book/

Учебник «Программирование дронов и создание автономных беспилотных миссий».

* `tex/` главы, оформление, рисунки, скриншоты симулятора.
* `data/` карты и словари маркеров для примеров навигации.
* `build.bat` сборка (XeLaTeX, minted, biber), результат в `build/` (в git не хранится).
* `main.pdf` актуальная собранная книга для чтения без сборки.

Код в книгу вставляется окружением `\begin{codefile}{lua/04_language/...}`: путь считается от каталога `examples/`.

## examples/

| Каталог | Что внутри |
|---|---|
| `lua/` | примеры глав по Lua (`02_sensors`, `03_rc_control`, `04_language`, `05_leds`, `06_missions`) |
| `lua-tasks/` | решения практических заданий |
| `python/` | скрипты на `pioneer_sdk`: основы, управление полётом, камера, ArUco, рой, навигация |
| `python-answers/` | ответы к упражнениям по Python |

Каждый файл, на который ссылается книга, прогоняет тест `simulator/tests/lessons-book-examples.test.ts`. Новый пример для книги: положить файл сюда, сослаться на него в главе, добавить ожидания в тест.

## third-party/

* `geoskan/` официальные материалы производителя.
* `web-docs/` сохранённые страницы документации (API Pioneer, пульт FlySky FS-i6S).

## Как части связаны

```
examples/ ──► book/tex        (codefile вставляет код в PDF)
    │
    └──────► simulator/       (список «Примеры» в редакторе; тест книги прогоняет каждый файл)
```

CI (`.github/workflows/web-simulator-ci.yml`) запускается при изменениях в `simulator/`, `examples/` и `book/tex/`.

## Что где менять

| Хочу | Куда |
|---|---|
| добавить пример | `examples/lua` или `examples/python`, затем ссылка в главе и ожидания в тесте |
| поправить текст книги | `book/tex/chapters/...`, сборка `book/build.bat` |
| изменить симулятор | `simulator/public/...` |
| положить чужой документ | `third-party/` |
| сохранить черновик | `archive/scratch/` |

## История решений

До октября 2026 всё лежало в `personal/lessons/...`: симулятор на семи уровнях вглубь (`personal/lessons/code/lua/web-simulator`), примеры в трёх копиях, результаты сборки книги в git. Структура переделана так, чтобы у каждого каталога было говорящее имя и одно назначение, а примеры имели единственный источник. Файлы переносились командой `git mv`, поэтому история сохранилась (`git log --follow <файл>`).

Что вынесено в `archive/`: первый симулятор на чистом Lua и черновики скриптов, лежавшие в корне. Что удалено: устаревшие скрипты, правившие пути (`scripts/`, `update_paths.py`), сохранённый вывод `git status`.
