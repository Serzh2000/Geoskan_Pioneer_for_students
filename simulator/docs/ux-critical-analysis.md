# Критический разбор интерактивного учебника

Дата: 2026-10-11. Объект: окно «Учебник пилота» (три трека: Python 108, Lua 72, Blockly 10).
Основа: [UX-CONTRACT.md](../UX-CONTRACT.md), живая страница (Lua, урок 4 «Повторный arm»,
Blockly, урок 1), замер контраста по трём трекам в обеих темах, код `mission-guide/`.

Степень уверенности: **H** — измерено на странице или видно в коде, **M** — вывод из
наблюдений, нужна проверка на учениках.

Контракт сильный по доступности, фокусу и слоям. Он **ничего не говорит про учебный цикл**
«написал → запустил → увидел». Именно здесь главные проблемы.

## Проблемы, по убыванию важности

### 1. Код и сцена разведены по разным экранам (H)
На шаге «Практика» нет сцены вообще (замер: `#mission-guide-scene-preview-host` отсутствует).
Дрон появляется только на шаге «Наблюдение». Ученик симулятора дрона не видит дрон, пока
пишет код, и не видит код, пока смотрит дрон. Это ломает цикл, ради которого сделан учебник.

### 2. Редактор ниже линии сгиба (H)
Верх редактора на странице находится на 709 px от начала прокручиваемой области. Шапка урока,
вкладки шагов и текст задачи занимают первые ~700 px. На экране высотой 900 px редактор виден
не полностью; на ноутбуке 768 px — почти не виден. Главное действие страницы спрятано.

### 3. Шесть обязательных экранов на урок (H)
Дрон → Понятие → Прогноз → Практика → Наблюдение → Разбор. До первой строки кода нужно
четыре перехода. 108 уроков × 6 шагов = 648 экранов. Нет пути для опытного ученика
(«я это знаю»), следующий урок заблокирован до разбора.

### 4. Один текст повторяется 4–5 раз (H)
Для урока 4: подзаголовок в шапке, шаг 1 (то же + «Тема урока»), шаг 2 «Одна идея» (то же
дословно), «Сегодня попробуем» (задание), «Ваша задача» (то же задание). На шаге 2 команда
`ap.push(Ev.MCE_PREFLIGHT)` показана дважды подряд: заголовок и пример совпадают.

### 5. Вопрос-прогноз можно угадать (H)
Номер правильного ответа задаётся чётностью номера урока (`index % 2` в `academy/practices/drone.ts`,
`number % 2` в `academy/practices/shared.ts`), вариантов два. Вопрос не измеряет понимание.

### 6. Результат проверки — список замечаний, а не картина происходящего (M)
Курс учит различать команду, состояние автопилота и наблюдаемый результат во времени.
Интерфейс показывает это текстом («Нужно исправить», карточки замечаний), хотя данные для
ленты времени уже есть: `walkthrough/state.ts` хранит образцы состояния дрона по времени.

### 7. Навигация смешивает язык и курс (M)
Вкладки «Python 108 / Lua 72 / Blockly 10» выглядят равноправными, но это три разные вещи:
два языка одного курса (разной длины, камера только в Python) и отдельный десятиурочный
курс. Число 72 против 108 не объяснено. Blockly по замыслу (`docs/blockly-unification-plan.md`)
должен быть режимом отображения кода, а не третьим курсом.

### 8. Шапка урока занимает слишком много (H)
Бейдж модуля, заголовок, пояснение, «Урок N из 108», «Предыдущий», «Следующий урок», подсказка
про блокировку — 5 уровней текста и две кнопки до первого содержимого. Кнопка «Следующий урок»
почти всегда неактивна, но занимает место и привлекает внимание.

### 9. Шаги — не вкладки и не мастер (M)
Шаги — обычные кнопки (`<button>`) с `aria-current="step"`; завершённые кликабельны, будущие
заблокированы. Это нормально, но одновременно есть «Шаг 4 из 6», вкладки шагов и «Дальше»/«Назад»:
три способа показать одно и то же.

## Что работает (оставить)
- Единое левое оглавление, раскрытый текущий модуль, сохранение черновиков.
- Честная блокировка запуска во время проверки, возврат к коду с сохранённым черновиком.
- Фокус-ловушка, inert для фона, Escape (контракт, раздел Focus).
- Пошаговая сборка Blockly с точными названиями блоков (добавлено в этой серии правок).

## Направление: «Бортовой самописец»
1. **Одно рабочее пространство вместо мастера.** Три области: брифинг (задание как чек-лист
   условий проверки, отметки в реальном времени) | код | живая сцена. Теория — свёрнутая
   карточка над брифингом, а не два экрана.
2. **Лента времени под сценой.** Дорожки: строка кода, команда, состояние автопилота, свет/высота.
   Прогноз ставится на ленте до запуска, результат ложится поверх. Перемотка и «призрак»
   прошлой попытки.
3. **Карта курса вместо аккордеона.** 12 этапов по полигонам; язык переключается внутри урока;
   Blockly — режим просмотра кода; «Я это знаю» — быстрая проверка вместо блокировки.
4. **Вопросы-прогнозы без угадываемого порядка**: случайный порядок вариантов, 3–4 варианта,
   объяснение после выбора.

## Предлагаемый порядок работ
1. Слить практику и наблюдение: сцена рядом с кодом (проблемы 1, 2, 4).
2. Сжать шапку и убрать повторы текста (4, 8).
3. Исправить генерацию прогнозов (5) — малая правка, высокая отдача.
4. Лента времени (6).
5. Карта курса и режим Blockly (7).

Не проверено: работа с клавиатуры по всем шагам, скринридер, поведение на планшете,
реальные данные об уроках, где ученики застревают. Для этого нужны сессии с учениками
или журнал `core/learning-journal.ts`.

## Сделано после разбора
- Сцена рядом с кодом на шаге «Практика» (проблемы 1, 2 частично) — Lua и Python.
- Прогнозы показываются в стабильном перемешанном порядке (5).
- Шапка короче, шаг «Понятие» не повторяет шаг «Дрон» (4, 8).
- «Знаю тему — сразу к прогнозу» (3, частично).
- Запись полёта на шаге «Наблюдение» (6) — по данным снимков, без новых источников.

Сознательно не сделано: карта курса и перенос Blockly в «режим кода» (7). Это смена
навигации, которой владеет контракт; без данных об учениках риск выше пользы.
