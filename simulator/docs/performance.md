# Производительность отрисовки

Симулятор рисует сцену на WebGL (three.js) на любом ноутбуке и на видеокартах уровня GTX 1060. Этот документ: какие правила
действуют для 3D в вебе, что именно тормозило в симуляторе (измерено, а не предположено), что сделано и какие бюджеты держать,
когда добавляешь контент.

## Правила, по которым считается кадр

Кадр в WebGL упирается в одно из трёх, и чинится оно по-разному.

| Узкое место | Что его даёт | Чем лечится |
|---|---|---|
| **CPU: отправка draw call** | каждый меш = отдельная команда (около 8 мкс в three.js: проверка видимости, материал, uniform-ы). Больше 1000 за кадр уже заметно, 3000 тяжело | склеивать статику по материалу, instancing, frustum culling, LOD (на расстоянии один меш вместо десяти) |
| **GPU: вершины и треугольники** | сумма за все проходы: основной, тень от солнца, `transmission` (ещё один проход всей сцены). Треугольник мельче пикселя стоит почти как крупный | LOD, упрощение сетки, не рисовать то, что не видно |
| **GPU: пиксели** | `devicePixelRatio` 2 даёт в четыре раза больше пикселей, MSAA, полупрозрачность (overdraw), `backdrop-filter` поверх живого canvas | ограничить DPR, меньше прозрачных слоёв, не блюрить то, что перерисовывается каждый кадр |

Правила попроще: сначала **измерь** (что именно ограничивает), потом оптимизируй; не меняй то, что не в узком месте; бюджет
на сцену (треугольники, draw call) задаётся заранее, а не вылавливается по жалобам.

Дополнительно в three.js: каждый свет считается для каждого пикселя каждого материала (даже с нулевой яркостью); `Raycaster`
перебирает **все** треугольники попавшего в bbox меша; `transmission` и `PointLight` дороги, `Object3D.visible = false` бесплатен.

## Что нашли в симуляторе

Замеры на Intel UHD (слабее GTX 1060 примерно в 4-5 раз): время GPU через `EXT_disjoint_timer_query_webgl2`, CPU через
`performance.now()` вокруг `renderer.render`. Карта «город», 600 м.

| Причина | Измерение | Что сделано |
|---|---|---|
| Модель дрона из Blender: **513 тыс. треугольников**, 185 мешей, 49 материалов, 5 из них с `transmission` | дрон давал 6-11 мс из 7-11 мс кадра стартовой сцены; без него кадр 0.4 мс. `transmission` удваивает число draw call. Файл 16 МБ | `tools/optimize_pioneer_glb.mjs`: **140 тыс. треугольников, 4.7 МБ**, без transmission; мелкие детали не отбрасывают тень |
| 5 нулевых `PointLight` на светодиодах каждого дрона | ABAB-замер: 71.5 мс с ними и 66.5 мс без них, то есть 7% кадра на пустом месте | убраны; свечение даёт emissive и спрайт |
| `applyShadows()` отключал frustum culling у каждого меша | уличный вид города: 8315 → 3805 draw call после включения | границы пересчитываются, отсечение включено |
| Многоэтажки: **3.4 млн из 4.7 млн треугольников карты** (балконные ограждения по 100 тыс. на дом) | обзор города: 3211 draw call, 6.5 млн треугольников, **GPU 71 мс** | дальний LOD: дом дальше порога рисуется одним боксом (`far-proxy.ts`, порог растёт с размером дома, гистерезис 10%); после: 305 draw call, 0.98 млн, **GPU 7.8 мс** |
| Дороги и рельсы сохранённой сцены не склеивались | 2902 меша на дороги и 4446 на рельсы вместо 132 и 9 | `rebuildLinearFeature` склеивает по материалу при каждой пересборке |
| Мастер пульта: второй полноэкранный рендерер с тяжёлым дроном, DPR до 2, 40 к/с; под ним отдельно рисовалась главная сцена | сцена мастера: 680 тыс. треугольников и 350 draw call за кадр | главная сцена не рисуется, пока мастер открыт (`render-gate.ts`); DPR до 1.5, 30 к/с; лёгкий дрон |
| `Raycaster` по большим склеенным мешам: рельсы (92 тыс. треугольников) 35 мс, рельеф 11 мс | луч дальномера/оптического потока и проверка метки стоили **65 мс**, а скрипт студента вызывает их в цикле | `scene/core/fast-raycast.ts`: сетка по треугольникам, тот же результат, что у three.js (тест сверяет); **2.4 мс** |
| Автоматический режим качества снижал качество только при медиане кадра > 33 мс | на слабых видеокартах пользователь долго жил на 25-30 к/с | порог 24 мс (~40 к/с) |

Что **не** оказалось причиной: дождь, снег и облака (вся погода 0.4-0.9 мс на кадр), анимация светодиодов, физика.

## Бюджеты для нового контента

* Один объект на карте: до 20 тыс. треугольников и до 8 мешей. Больше: делать упрощённый вариант для дальнего расстояния
  (`attachFarProxy`).
* Дрон: до 150 тыс. треугольников, без `KHR_materials_transmission`, без `PointLight`. После каждого экспорта из Blender
  прогонять `tools/optimize_pioneer_glb.mjs`.
* Повторяющиеся объекты (деревья, фонари, светофоры): `InstancedMesh`, не по мешу на штуку.
* Новый меш, по которому бьют лучами (датчики, редактор): если в нём больше 1500 треугольников, ускоритель включится сам.
* Новая UI-панель поверх canvas: без `backdrop-filter`, если она на экране постоянно.

## Как измерять

* `?render-metrics` в адресе: на бейдже FPS появляются медиана и p95 кадра, draw call, треугольники.
* В консоли страницы: `renderer.info.render` (calls, triangles) после `renderer.render(...)`; для времени GPU запрос
  `EXT_disjoint_timer_query_webgl2`. Сравнивать A/B несколько раз подряд (ABAB): единичный замер на ноутбуке шумит.
* Вкладка в фоне не рисует и тормозит таймеры: измерять только на видимой странице.
