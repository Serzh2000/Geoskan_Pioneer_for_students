# Python Runtime (`server/python-runtime.ts`)

Запускает **присланный от клиента Python-код** локальным процессом
(`child_process.spawn`) через обёртку из [[Python Bridge (python_bridge)]],
подставляющую параметры подключения к `pioneer_sdk`.

Это осознанная фича симулятора (запуск «настоящего» Python), но сервер
выполняет произвольный код по запросу. Прод-деплой публично доступен из
интернета без авторизации (ученики заходят по домену) → базовые ограничения
обязательны в проде:

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `CORS_ORIGIN` | список разрешённых origin через запятую | открыто всем (!) |
| `RATE_LIMIT_MAX` / `RATE_LIMIT_WINDOW_MS` | лимит запросов к `/api/*` на IP | 30 / 60с |
| `TRUST_PROXY_HOPS` | число хопов до реального клиента за прокси | — |
| `PYTHON_RUNTIME_MAX_CONCURRENT` | сколько раннеров одновременно | 20 |
| `PYTHON_RUNTIME_MAX_SCRIPT_LENGTH` | макс. размер скрипта, символов | 200 000 |
| `PYTHON_RUNTIME_CPU_LIMIT_SECONDS` / `_MEMORY_LIMIT_KB` | `ulimit` на процесс (Linux/macOS, не Windows) | — |

**Не является полноценной песочницей** — процесс выполняется с правами
пользователя Node, без изоляции сети/файловой системы. Следующий шаг —
Docker-контейнер с `--network=none` на процесс (на момент написания README
сервер работает на Linux без Docker). См. [[Известные ограничения и риски]].
