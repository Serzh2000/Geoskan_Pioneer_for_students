# Debug Session: takeoff-go-to-point

Status: OPEN

## Symptom

- Официальный Python-скрипт вызывает `pioneer.takeoff()` и затем `pioneer.go_to_local_point(...)`.
- В симуляторе это падает с `FSM error: invalid transition from TAKEOFF_PROCESS by command GO_TO_LOCAL_POINT`.

## Initial Hypotheses

1. Веб-симулятор требует завершить фазу `TAKEOFF_PROCESS` до первого `go_to_local_point(...)`, а официальный SDK допускает раннюю постановку цели.
2. Метод `takeoff()` в симуляторе не переводит дрон в состояние, совместимое с немедленным `go_to_local_point(...)`, хотя документационные сценарии на это рассчитывают.
3. Ошибка вызвана не самим `go_to_local_point(...)`, а отсутствием промежуточного ожидания достижения высоты после `takeoff()`.
4. Python bridge должен смягчать это различие совместимости и откладывать первый `go_to_local_point(...)` до завершения взлёта.
5. FSM симулятора слишком строгая по отношению к официальным миссионным примерам и нуждается в совместимом переходе или очереди команды.

## Plan

- Собрать доказательства по переходам FSM на связке `takeoff()` -> `go_to_local_point(...)`.
- Определить, где именно расходится поведение симулятора и официального SDK.
- Внести минимальный совместимый фикс без регрессии других полётных сценариев.
