# Эмуляция Swarm Kit (pioneer_swarm) в симуляторе: устройство, допущения, консоль

Эталон поведения - `docs/swarm/swarm-kit.md` (docs.geoscan.ru). Здесь записано то, чего в нём нет и что пришлось выбрать.

Swarm Kit - часть режима «Python · SDK2» (Мини 2 и Базовый с Radxa Zero 3W), отдельного языка нет. В режиме SDK1 `import pioneer_swarm` отклоняется до запуска с номером строки и подсказкой выбрать «Python · SDK2» (`checkPythonSdkForDrone`, как у rclpy).

## Модель сети

- **Юнит = swarm-server одного дрона.** Он есть у каждого дрона сцены с `pioneer_sdk2` (Мини 2; Базовый с Radxa) и работает всегда, как на настоящем борту: без программы ученика дрон шлёт Heartbeat, отдаёт телеметрию подписавшимся и принимает письма. Дроны на SDK1 (Базовый без Radxa) в рое не появляются.
- **Объект `PioneerSwarmUnit` = клиент сети** в программе ученика. Привязывается к дрону программы (раннер кладёт `__sim_drone_id` в глобальные переменные программы, поэтому привязка верна, даже если после неё стартовала программа другого дрона). `close()` или конец программы закрывают объект; swarm-server дрона остаётся.
- **machine_id.** Номер берётся из конца имени дрона («Пионер Мини 2 · 3» -> `pioneer3`); если он занят или его нет, достаётся наименьший свободный. Идентификатор зависит только от имён и порядка дронов в панели «Рой», где он показан под названием дрона. Свой `machine_id=...` в конструкторе (латинские буквы, цифры, `_`) переименовывает юнит дрона, пока объект открыт; занятый идентификатор - `RuntimeError`.
- **Время.** Часы сети - общие часы симуляции (`simClock`, секунды физики, идут и у дронов без программ, не откатываются кнопкой «Сначала»). Ожидание телеметрии ждёт по ним же через `asyncio` (как `spin` и блокирующие вызовы SDK), поэтому остальные дроны работают, пока одна программа ждёт; «Стоп» прерывает ожидание. `time.sleep` в программе, как везде в симуляторе, - настенные секунды.

## Допущения там, где справочник молчит

**Числа сети.** Heartbeat раз в секунду. Юнит пропадает из `get_unit_list()`, если его Heartbeat не слышен 3 секунды (три периода): удалённый дрон, дрон с другим языком, выключенный swarm-server. Дрон, добавленный на глазах у работающей программы, появляется в списках после своего первого Heartbeat (полсекунды). Первый собственный Heartbeat: `unit_type` равен `None` первые 0.5 с после создания объекта, потом `SwarmUnitType.AERO`. Новый клиент сразу видит всех соседей, которые есть в сети (допущение: Heartbeat хранит последнее значение, как transient-local QoS), а не ждёт их очередных Heartbeat.

**Список соседей.** `get_unit_list()` - по возрастанию номеров (`pioneer2`, `pioneer10`), себя нет. Порядок обнаружения у настоящей библиотеки не задан; сортировка - для детерминизма.

**Исключения.** Справочник говорит «без определённого machine_id объект не создастся»: выбрано `RuntimeError` с русским текстом (дрона нет в симуляторе; пустая строка `machine_id`; дрон не на SDK2). Неверные типы - `TypeError` (`domain_id` не `int`, `machine_id`, `unit_id`, `message` не `str`, `timeout_sec` не число), неверные значения - `ValueError` (`domain_id` вне 0..232, недопустимые символы в `machine_id`, отрицательный `timeout_sec`). Вызов метода после `close()` - `RuntimeError`.

**Домены.** Юнит находится в домене 0, пока в нём не открыт объект; объект с `domain_id=N` переводит swarm-server своего дрона в домен N на время жизни объекта (допущение: домен задаётся конфигурацией борта, которую библиотека разделяет с swarm-server). Соседи видны только внутри домена; письма и телеметрия в другой домен не доходят (`False`, `None`). Домен swarm-server дрона без программы задаёт консоль (`SwarmRegistry.setDomain`).

**Сообщения.** Только строки; доставка мгновенная, порядок сохраняется. `send_message_to_unit` возвращает `False` для юнита вне списка, в том числе себя. Ящик ограничен 100 сообщениями (старые вытесняются). Ящик принадлежит юниту: письма соседу без программы ждут его программу. Ящик очищается, когда закрывается последний объект юнита (`close()`, конец программы), и пропадает вместе с юнитом. Несколько объектов на одном дроне читают из одного ящика.

**Телеметрия.** Подписка принадлежит объекту и держится до `close()` (или пока сосед не пропадёт); пока подписчиков нет, поток на сеть не льётся (учтено в `unit_info().subscribers`). `get_telemetry_from_unit(unit_id, timeout_sec=60.0)`:
- `None`, если юнита нет в списке соседей (в том числе себя); иначе `(SwarmUnitType.AERO, dict)`;
- первый вызов подписывает на все потоки каталога и ждёт, пока придёт по сэмплу каждого периодического потока (самый медленный - `sensors/battery_state` с периодом 0.5 с; первые сэмплы не раньше чем через 0.1 с после подписки), но не дольше `timeout_sec`; потом возвращает накопленное: при коротком таймауте словарь может быть неполным или пустым;
- `timeout_sec=0` - только подписаться и вернуть накопленное, `None` - ждать все потоки без ограничения; если сосед пропал во время ожидания - `None`;
- значения - объекты сообщений ROS 2 из эмуляции `rclpy` (`geometry_msgs.msg.Point` и т. д.); словарь отдаёт копии. Сообщения подгружаются при первом запросе телеметрии, до того ROS 2 не загружается.

**Каталог потоков воздушного юнита** (имена без идентификатора юнита, полное имя в сети - `pioneer1/navigation/local/position`; допущение: то же, что у топиков `ros_pioneer_node` без префикса `/geoscan/`, те же типы и единицы, что в `docs/ros2/emulation-notes.md`):

| Поток | Тип | Период |
|---|---|---|
| `navigation/local/position` | `geometry_msgs/msg/Point` | 0.05 с |
| `navigation/local/velocity` | `geometry_msgs/msg/Vector3` | 0.05 с |
| `navigation/local/yaw` | `std_msgs/msg/Float32` (радианы) | 0.05 с |
| `navigation/local/status` | `gs_interfaces/msg/NavStatus` (всегда 3, OK) | 0.05 с |
| `sensors/imu` | `sensor_msgs/msg/Imu` | 1/30 с |
| `sensors/altitude` | `std_msgs/msg/Float32` | 0.1 с |
| `sensors/battery_state` | `sensor_msgs/msg/BatteryState` | 0.5 с |
| `flight/fly_state` | `std_msgs/msg/Int8` (0 на земле, 1 моторы, 2 в воздухе) | 0.1 с |
| `flight/callback_event` | `std_msgs/msg/Int8` | по событию |

Каталог (Heartbeat) на сеть описан константой `_STREAMS` в `swarm/prelude.ts`. Поток `flight/callback_event` появляется в словаре только после события с момента подписки: коды `Event` из `pioneer_sdk2` (1 DISARM, 2 COPTER_LANDED, 3/4 LOW_VOLTAGE, 7 TAKEOFF_COMPLETE, 8 ENGINES_STARTED, 9 SHOCK); событий точки (5, 6) нет, потому что флаг точки принадлежит SDK и снимается одним читателем. События считаются по смене состояния автомата дрона между опросами сети. Датчики `range`, `motors_rpm`, `optical_flow`, `ranger`, GNSS в рое не объявляются.

**Типы юнитов.** Все дроны симулятора - `AERO`. `ROVER`, `MARINE`, `ROBOT`, `OTHER` есть в перечислении (значения - строки `'aero'`, `'rover'`, ...: допущение), но юнитов таких типов в симуляторе нет.

**Одна программа за раз.** Кнопка «Запуск» запускает Python только выбранного дрона, но программы других дронов продолжают работать: чтобы запустить рой, выберите дрон, загрузите его программу и нажмите «Запуск», потом то же на втором дроне. Поэтому примеры из двух частей лежат отдельными файлами (`swarm_05_follow_leader.py` / `swarm_05_follow_follower.py`) с пояснением в шапке; порядок запуска - сначала ожидающая сторона.

## Консоль и панели: что можно получить

```ts
import { createSwarmRegistry } from '.../python/swarm/browser-host.js';
const swarm = createSwarmRegistry(currentDroneId);

await swarm.units();               // все юниты: machine_id, drone, domain, visible, online, age, mailbox, instances, subscribers
await swarm.unitInfo('pioneer2');  // + каталог потоков из Heartbeat и число подписчиков на каждый
await swarm.mailbox('pioneer2');   // [[отправитель, текст], ...] без извлечения
await swarm.send('pioneer2', 'text', 'console');   // письмо «с земли»
await swarm.telemetry('pioneer2', 5);              // временная подписка, значения - repr сообщений
await swarm.setOnline('pioneer2', false);          // выключить swarm-server: пропадёт через 3 с
await swarm.setDomain('pioneer2', 1);              // домен swarm-server юнита без программы
await swarm.clock();  await swarm.reset();
```

Ошибки приходят как `SwarmError` с русским текстом (юнит не найден и т. п.). Фасад работает без программы ученика и без запущенного ROS 2.

## Что не сделано

- Нет UI-панели роя (список юнитов, ящики, подписки): только machine_id в строке дрона панели «Рой» и фасад для неё.
- Единственный тип юнита - воздушный; сторонние юниты (ровер, судно) и Heartbeat других типов не эмулируются.
- Нет настоящей сети: задержек, потерь, перегрузки канала.
- Ящик и подписки не переживают закрытие объекта; сообщения не имеют идентификаторов и подтверждений.
- Кнопка «Сначала» не очищает ящики напрямую: они очищаются, когда программа закрывает объект (остановка программы).
