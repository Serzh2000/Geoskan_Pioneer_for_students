# Swarm Kit и pioneer-swarm — справочник Геоскана

Источник: документация Pioneer OS на docs.geoscan.ru (скопировано пользователем 10.11.2026; эталон для эмуляции в симуляторе и для главы учебника).

Swarm Kit — набор программных инструментов для создания роев. Доступен на всех устройствах с Pioneer OS, начиная с версии 1.0.0 (старый образ нужно обновить).

## Что такое Swarm Kit
Дроны (и другие устройства) в одной сети находят друг друга, обмениваются сообщениями и делятся телеметрией. В рое нет центрального сервера и нет выделенной наземной станции. Все юниты равноправны: подключаются к общей сети (Wi‑Fi или Ethernet) и общаются напрямую. У каждого есть имя — идентификатор (`machine_id`), по которому к нему обращаются остальные.

```
  ┌─────────┐         общая сеть          ┌─────────┐
  │  Юнит A │ ←─────────────────────────→ │  Юнит B │
  └─────────┘                             └─────────┘
                     ↕
                ┌─────────┐
                │  Юнит C │
                └─────────┘
```

### Участники роя
Участник — юнит (борт). Он одновременно объявляет себя в сети и публикует данные с датчиков; видит других юнитов, читает их телеметрию и пишет им сообщения. Типы юнитов (воздушный, наземный и т.д.) различаются набором данных, которые они объявляют. На Pioneer и Mini 2 в рое обычно появляется тип воздушный (aero): позиция, скорость, IMU, высота, батарея и события полёта.

### Три вида общения
1. **Обнаружение: «кто в сети?»** Каждый юнит периодически рассылает короткий сигнал — Heartbeat («я жив»), в нём: свой тип и каталог доступных данных (какие потоки телеметрии готов отдавать). Соседям не нужно заранее знать полный список потоков: из Heartbeat понятно, на что можно подписаться. Новый тип устройства можно добавить, не меняя остальных юнитов.
2. **Телеметрия: «что происходит у соседа?»** Юнит подписывается на нужные потоки соседа (позиция, батарея и т.д.). Сосед отдаёт данные тем, кто подписался. Пока подписчиков нет, поток на сеть не льётся — экономия канала. Имена потоков всегда начинаются с идентификатора юнита, например `pioneer1 / navigation / local / position` — локальная позиция юнита pioneer1.
3. **Сообщения: «написать юниту»** У каждого юнита есть почтовый ящик — входящие текстовые сообщения. Чтобы написать pioneer1, другой юнит отправляет строку в его ящик. Содержимое протоколом не регламентируется: команда приложения, статус или произвольный текст.

### Типичный сценарий
Несколько юнитов в одной сети, один и тот же домен роя. На каждом борту работает `swarm-server` — юнит появляется в сети и шлёт Heartbeat. Приложение на юните через `pioneer-swarm` получает список соседей, читает телеметрию выбранного соседа и/или обменивается с ним текстовыми сообщениями. Если юнит пропал из сети — он исчезает из списка; подписки на него можно снять.

## pioneer-swarm
Python-библиотека для работы с роем для приложений на юните. Возможности:

| Возможность | Смысл |
|---|---|
| Список юнитов | Кто сейчас виден в сети (кроме себя) |
| Отправить сообщение | Текст на конкретный machine_id |
| Прочитать входящие | Сообщения, пришедшие в свой ящик (кто написал и что) |
| Телеметрия | Подписаться по описанию из Heartbeat и получить актуальные данные |
| Тип юнита | Воздушный, наземный и др. — из маячка соседа |

Поток работы: подключиться к рою → узнать список соседей → (прочитать телеметрию) → (отправить / принять сообщения) → закрыть соединение. Библиотека сама следит за появлением и исчезновением юнитов и подстраивает подписки под то, что сосед объявил в Heartbeat; детали обнаружения и имён топиков скрыты внутри.

### API
```python
from pioneer_swarm import PioneerSwarmUnit, SwarmUnitType
swarm = PioneerSwarmUnit()
# ... работа с роем ...
swarm.close()
```

Создание: `PioneerSwarmUnit(domain_id=0, machine_id=None, sync_wait_timeout_sec=None)`

| Параметр | По умолчанию | Смысл |
|---|---|---|
| domain_id | 0 | домен роя — у всех юнитов должен совпадать |
| machine_id | авто | свой идентификатор; не обязателен — определяется автоматически с борта |
| sync_wait_timeout_sec | авто | сколько ждать появления id, если он ещё неизвестен |

Без определённого machine_id объект не создастся.

Свойства: `.id` (str) — свой machine_id; `.unit_type` (SwarmUnitType или None) — свой тип юнита (появляется после первого собственного Heartbeat).

Методы:
- `get_unit_list() -> list[str]` — идентификаторы соседей в сети (себя не включает).
- `send_message_to_unit(unit_id: str, message: str) -> bool` — отправить текст юниту unit_id. True — адресат найден и сообщение ушло; False — юнита в списке нет.
- `get_next_message() -> tuple[str, str] | None` — следующее входящее сообщение из своего ящика, без ожидания; очередь пуста — None. Кортеж `(sender_id, text)`.
- `get_telemetry_from_unit(unit_id: str, timeout_sec: float | None = 60.0) -> tuple[SwarmUnitType, dict] | None` — дождаться телеметрии соседа (или вернуть то, что накопилось к концу таймаута). None — юнит не найден. Иначе `(тип юнита, словарь потоков)`, например `"navigation/local/position"` → данные. `timeout_sec=None` — ждать без ограничения.
- `close() -> None` — остановить слежение и отключиться от роя; вызывать, когда работа закончена.

Тип юнита `SwarmUnitType`: AERO — воздушный, ROVER — наземный, MARINE — водный, ROBOT — робот, OTHER — иное / неизвестное.

Пример:
```python
from pioneer_swarm import PioneerSwarmUnit, SwarmUnitType
swarm = PioneerSwarmUnit()
print("Я:", swarm.id, swarm.unit_type)
for unit_id in swarm.get_unit_list():
    swarm.send_message_to_unit(unit_id, "ping")
    result = swarm.get_telemetry_from_unit(unit_id, timeout_sec=5.0)
    if result is not None:
        unit_type, telemetry = result
        if unit_type == SwarmUnitType.AERO:
            print(unit_id, "— воздушный", telemetry)
incoming = swarm.get_next_message()
if incoming is not None:
    sender, text = incoming
    print("От", sender, ":", text)
swarm.close()
```

## Что важно запомнить
- Рой одноранговый — только юниты между собой, без наземного центра.
- У каждого есть имя (machine_id) — по нему строятся «адреса» данных и почтовый ящик.
- Heartbeat — способ сказать «я здесь» и «вот что у меня есть».
- Телеметрия идёт по подписке; сообщения — в личный ящик юнита.
- pioneer-swarm — удобный способ писать бортовые приложения поверх этого устройства.
