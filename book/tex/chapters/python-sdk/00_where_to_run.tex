\section{Pioneer SDK: полёт из Python}
\label{sec:python-sdk}

\begin{infobox}[Цели главы]
\begin{itemize}
    \item Запускать Python-программу в симуляторе, на настоящем дроне и с компьютера на симулятор.
    \item Подключаться к дрону, читать телеметрию и управлять подсветкой через \texttt{led\_control}.
    \item Выполнять взлёт и посадку безопасно: пауза после \texttt{arm()}, ожидание после \texttt{land()}.
    \item Летать по точкам и фигурам, дожидаясь каждой точки через \texttt{point\_reached()}.
    \item Ждать подтверждений с ограничением по времени, читать измерения и сравнивать их с целью с допуском.
\end{itemize}
\end{infobox}

\begin{missionbox}[Миссии симулятора к главе]
Язык \ui{Python}, панель \ui{Обучение}. Порядок миссий совпадает с порядком уроков главы.
\begin{itemize}
    \item \textbf{10--18 «Сигналы и подсветка»}: первый красный свет, номер светодиода, зелёный и синий, смешиваем белый, выключаем сигнал, свет и подтверждение, цвет как переменная, таблица сигналов, световой отчёт подготовки.
    \item \textbf{28--36 «Время и события»}: пауза делает цвет видимым, отложенный сигнал, два таймера, повторяющийся ритм, получаем уведомление, не реагируем на всё подряд, помним текущий этап, ждём не бесконечно, готовность без угадывания.
    \item \textbf{37--45 «Высота и координаты»}: первая высота, три оси, знак направления, где начало, одна точка маршрута, высота над поверхностью, расстояние до цели, допуск прибытия, курс корпуса.
    \item \textbf{46--54 «Маршрут по этапам»}: подтверждаем точку, две точки, угол маршрута, замыкаем квадрат, список точек, возвращение домой, первая посадка, полный короткий полёт, повторяемость маршрута.
    \item \textbf{55--63 «Полигоны и местность»}: один seed --- одна карта, свободная стартовая зона, лесной коридор, холмы и высота, обход здания, промышленный участок, гоночный полигон, новый seed, маршрут через разные зоны.
    \item \textbf{64--72 «Измерения и устойчивость»}: читаем положение, как часто измерять, нет данных, достигли высоты, ошибка положения, не дёргаемся у границы, ограничиваем действие, причина остановки, отчёт полёта.
\end{itemize}
\end{missionbox}

\subsection{Где запускать Python}

Для управления Пионером из Python есть библиотека \texttt{pioneer\_sdk}: команды взлёта, посадки, полёта в точку, светодиоды, телеметрия, камера. У Python-программы, как и у Lua, два исполнителя.

\subsubsection*{В симуляторе}

Выберите в редакторе язык \ui{Python}. Библиотека уже «установлена»: \verb|from pioneer_sdk import Pioneer| работает, а дрон на сцене выполняет команды. Вывод \verb|print| --- в терминале, как и для Lua. Программа выполняется в браузере (интерпретатор Pyodide), поэтому адрес в \verb|Pioneer(ip=...)| здесь ни на что не влияет: команды получает выбранный на сцене дрон.

\begin{infobox}[Чего нет у настоящего pioneer\_sdk]
Справочник редактора (кнопка с книгой) описывает и команды, которые есть только в симуляторе: \verb|Camera(view="bottom")| --- нижняя камера (глава~\ref{sec:python-vision}), \verb|get_optical_flow()| --- датчик оптического потока, \verb|Vehicle| --- машины и поезда сцены. \verb|get_yaw()| и \verb|cargo_grab()|/\verb|cargo_release()| есть лишь в версии pioneer\_sdk~0.6.1 с GitFlic и работают только при \verb|Pioneer(simulator=True)|. В программах для настоящего дрона этих команд не используйте.
\end{infobox}

\subsubsection*{На настоящем дроне}

Python-программа работает на вашем компьютере и общается с дроном по Wi-Fi:

\begin{codebox}[Терминал]
\texttt{pip install pioneer-sdk}
\end{codebox}

Дрон создаёт сеть Wi-Fi (имя вида \texttt{Pioneer\_...}); подключитесь к ней --- и \verb|Pioneer()| найдёт дрон по адресу по умолчанию.

\subsubsection*{С компьютера --- на симулятор}
\label{sec:python-external}

Третий вариант: программа на вашем компьютере, а летает дрон в симуляторе. На сайте у дрона включается \ui{Разрешить внешние команды}, а в программе вместо адреса дрона указывается адрес сайта:

\begin{codebox}[Подключение к симулятору]
\begin{verbatim}
from pioneer_sdk import Pioneer
pioneer = Pioneer(ip='simulator.sakoryagin.ru',
                  mavlink_port=8001)
\end{verbatim}
\end{codebox}

Точный фрагмент подключения (у каждого дрона сцены свой порт) показывает панель подключения дрона; там же --- фрагмент для камеры. Дальше программа ничем не отличается от программы для настоящего дрона. Так удобно отлаживать то, что в браузере недоступно: сторонние библиотеки, запись файлов, полноценный OpenCV.

\begin{infobox}[Lua ждёт событий, Python --- опрашивает]
В Lua следующую команду отдают из \verb|callback| по событию. В Python программа сама периодически спрашивает автопилот: \verb|while not pioneer.point_reached(): time.sleep(0.1)|. Смысл тот же --- не отдавать следующую команду, пока предыдущая не выполнена, --- меняется только форма.
\end{infobox}

\begin{taskbox}[Первая связь]
В симуляторе напишите программу из трёх строк: импорт \verb|Pioneer|, создание объекта \verb|pioneer = Pioneer()| и вывод \verb|pioneer.get_autopilot_state()|. Затем добавьте перед выводом \verb|pioneer.arm()| и сравните результат. Дрон не должен взлететь.
\expected{сначала в терминале \texttt{DISARMED}; после добавления \texttt{arm()} --- \texttt{ARMED}, винты вращаются, дрон стоит на площадке.}
\mission{Python}{3--5}
\end{taskbox}
