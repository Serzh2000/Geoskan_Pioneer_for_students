## 🖼️ Как это выглядит

### Пишем код и сразу видим полёт

<img src="docs/readme/editor-dark.png" alt="Редактор кода Lua с подсветкой синтаксиса" width="900">

Редактор на Monaco: подсказки по функциям Пионера, подсказки по аргументам при наборе скобки, русские псевдонимы в автодополнении, проблемы и вывод в терминале.

### Справочник API под рукой

<img src="docs/readme/api-reference-dark.png" alt="Справочник API: категории, синтаксис, аргументы и примеры" width="900">

Около 140 записей по категориям: синтаксис, аргументы, единицы измерения, возвращаемое значение и пример, который копируется одной кнопкой. У команд и событий автопилота есть явные пометки: **«→ автопилот»** (программа отправляет команду) и **«← от автопилота»** (событие приходит в `callback`). Справочник сверен с официальным `pioneer_sdk` и документацией Lua API, а примеры в нём разбираются и проверяются тестами.

### Учебник внутри симулятора

<img src="docs/readme/textbook-dark.png" alt="Учебник пилота: уроки Python, Lua и Blockly с пошаговыми заданиями" width="900">

Урок разбит на пять шагов: идея, прогноз, практика, результат, разбор. Если в программе ошибка, симулятор не просто пишет «error»: объясняет по-человечески и ведёт на нужный урок.

### Академия: уроки с проверкой полётом

Режим обучения ведёт ученика по главам: от первой команды `arm` и светодиодов до таймеров, маршрутов, датчиков, камеры, ArUco-меток и самостоятельных миссий. В каждой миссии:

1. короткое объяснение «как это устроено»: что за устройство или метод, как задаются параметры (порядок аргументов, единицы, диапазоны), что будет видно в результате;
2. задание с шагами и пропуском `___` в готовой программе;
3. кнопка «Проверить полёт»: симулятор реально запускает программу и проверяет события, положение дрона, светодиоды и журнал, а не текст кода;
4. понятное замечание, если что-то не так, и подсказка по шагам.

Часть миссий состоит из нескольких опытов (например, сначала зелёный, потом синий): проверка запоминает подтверждённые опыты и говорит, какой запуск остался. Python-линия содержит 124 миссии (в том числе машинное зрение и наведение по метке), Lua-линия 93, Blockly 16.

### Кабинеты учителя и ученика

Без входа всё работает как раньше, прогресс остаётся в браузере. Для класса есть аккаунты:

* **Ученик** регистрируется сам. В «Моём кабинете»: карточка «Продолжить», прогресс по трём языкам, список миссий, история своих попыток с кодом, календарь активности, серия дней, достижения, профиль.
* **Учитель**: обзор класса (кто занимался, кто застрял, кто давно не заходил), группы, массовое создание учеников со случайными паролями, таблица «ученик × миссия», ручной зачёт с комментарием, отчёт CSV, страница ученика с историей попыток и кодом.
* **Где застревают**: миссии, где чаще всего не проходит проверка, с частыми замечаниями. Если много людей получают одно и то же замечание, формулировка задания написана непонятно.
* **Приватность**: код хранится только у учеников с аккаунтом, об этом сказано в окне входа. Анонимная метрика (без имён и кода) показывает, какие миссии чаще бросают.

Устройство, данные и развёртывание: [simulator/README.md](simulator/README.md) и [simulator/docs/cabinets.md](simulator/docs/cabinets.md).

## 🚀 Быстрый старт

Самый простой путь: открыть [simulator.sakoryagin.ru](https://simulator.sakoryagin.ru).

Локально (нужен Node.js 20+):

```bash
cd simulator
npm install
npm start          # сервер примеров + Vite на http://localhost:3011
```

Проверки:

```bash
npm run type-check                                  # TypeScript
npm test                                            # весь набор: 1700+ тестов
npm test -- tests/lessons-book-examples.test.ts     # все примеры книги в симуляторе
```

Часть тестов (генерация города, толпа людей) проверяет скорость и на загруженной машине может упасть по времени: перезапустите её отдельно.

Сборка учебника (TeX Live 2024+, XeLaTeX, biber, Python с `pygments`):

```bat
personal\lessons\build.bat
```

## 📂 Структура репозитория

```
├─ simulator/      веб-симулятор (TypeScript, Three.js, Monaco, Blockly) и его тесты
├─ book/           учебник: исходники LaTeX, данные для примеров навигации, сборка
├─ examples/       все примеры: единственный источник и для книги, и для симулятора
│  ├─ lua/         примеры глав по Lua (02_sensors, 03_rc_control, 04_language, 05_leds, 06_missions)
│  ├─ lua-tasks/   решения практических заданий
│  ├─ python/      скрипты на pioneer_sdk: камера, ArUco, рой, навигация
│  └─ python-answers/  ответы к упражнениям по Python
├─ third-party/    чужое, только для чтения
│  ├─ geoskan/     официальные материалы производителя
│  └─ web-docs/    сохранённые страницы: API Pioneer, пульт FlySky FS-i6S
├─ docs/           картинки для README и описание структуры
└─ archive/        устаревшее и черновики
```

Идея проста: **что запускаем** (`simulator`), **что читаем** (`book`), **чему учим** (`examples`), **чужое** (`third-party`). Подробности и история решений в [docs/repo-structure.md](docs/repo-structure.md).
