# Debug Session: camera-video-stream

Status: OPEN

## Симптом

- На `Python 3.13` полет по локальной точке уже работает корректно.
- Примеры с камерой из `pioneer-python-example`, например `camera_examples/take_photo.py`, работают некорректно.
- Ожидается получение фото/видеопотока из симулятора через `pioneer_sdk.Camera`.

## Ожидание

- Внешний Python-скрипт с ПК должен подключаться к браузерному симулятору.
- Вызовы `Camera.get_frame()` / `Camera.get_cv_frame()` должны возвращать данные из симулятора, а не пустой результат.
- Примеры `take_photo.py` и потоковые сценарии должны работать без реального дрона.

## Фальсифицируемые гипотезы

1. Python bridge патчит только `Pioneer`, но не зеркалит/не перенаправляет `Camera`, поэтому внешний Python пытается работать с реальной камерой вместо браузерной.
2. Browser runtime умеет выдавать кадры только для встроенного Python в браузере, а внешний HTTP bridge не передает события/состояние для камеры.
3. Симулятор выдает кадры только при выполнении дополнительных условий сцены, и пример падает из-за пустого кадра без явной ошибки.
4. Внешний Python получает не байты изображения, а служебный payload/пустой буфер, несовместимый с примерами `take_photo.py` и OpenCV/PIL.
5. Проблема зависит от конкретного API-метода: `get_frame()` и `get_cv_frame()` реализованы по-разному, и ломается только один из путей.

## План

- Добавить только инструментирование, без изменения бизнес-логики.
- Собрать runtime-логи по вызовам `Camera` в Python bridge, server bridge и browser runtime.
- Подтвердить, на каком участке теряется кадр: Python -> HTTP bridge -> browser -> camera provider.
- После подтверждения причины внести минимальный фикс и сравнить pre-fix / post-fix.
