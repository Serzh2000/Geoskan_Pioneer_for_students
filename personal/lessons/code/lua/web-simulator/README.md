# Web Simulator

Браузерный симулятор дрона Pioneer для учебных занятий: 3D-сцена (Three.js/Babylon),
редактор кода (Monaco + Blockly) на Lua или Python, физика полёта и мост к
реальным протоколам (MAVLink, `pioneer_sdk`) через локальный Node-сервер.

Это не исчерпывающая документация, а карта для быстрой ориентации — что где
лежит и как связаны части системы.

## Быстрый старт

```bash
npm install
npm start        # сервер (порт 3000) + Vite dev-server (порт 3001) параллельно
```

Прод-сборка:

```bash
npm run build     # vite build + компиляция server.ts в dist/
npm run prod      # build + запуск dist/server.js
```

Проверки:

```bash
npm run type-check
npm run lint
npm test
```

CI (`.github/workflows/web-simulator-ci.yml` в корне монорепозитория) гоняет
все три проверки на push/PR, если менялись файлы этого проекта.

## Как устроено

### Клиент (`public/`)

Точка входа — [public/main.ts](public/main.ts): собирает 3D-сцену, редактор,
UI и раннер скрипта, дальше вся логика живёт в `public/modules/`:

| Модуль | Что делает |
| --- | --- |
| `core/` | Общее состояние симуляции: `simState` (текущий дрон), `drones` (реестр всех дронов), `simSettings`. См. «Состояние» ниже. |
| `drone/` | Обвязка над 3D-объектом дрона: обновление позиции/ориентации, сброс, операции над сценой. |
| `physics/` | Модель полёта (ручной и авто-режимы), интеграция скорости/позиции по `dt`. |
| `autopilot/` | Конечный автомат полёта (FSM), события MCE, обработка параметров автопилота. |
| `lua/` | Раннер Lua-скриптов на Fengari (Lua в WASM/JS), API для скрипта (`ap`, `Sensors`, `Timer`, `camera`), диагностика падений скрипта. |
| `python/` | Два режима исполнения Python: браузерный JS-bridge (`pioneer-js-bridge*`) и обвязка над серверным runtime/внешним bridge (`external-bridge*`, `local-runtime.ts`). |
| `editor/` | Monaco (текстовый режим) и Blockly (визуальный режим), автодополнение, переключение режимов. |
| `scene/`, `environment/` | 3D-сцена, объекты, окружение (земля, препятствия, разметка). |
| `ui/` | Все панели интерфейса: настройки, менеджер дронов, `mission-guide` (методические уроки), api-docs, гейммпад и т.д. Самый большой раздел проекта. |
| `app/` | Верхнеуровневая склейка: уведомления о выполнении скрипта, переключатель языка/темы, цикл анимации. |
| `shared/` | Общие утилиты (логирование и т.п.). |

`ui/mission-guide/` — отдельного внимания заслуживает контент уроков
(`lessons/`, `curriculum/`): методический текст и сценарии проверки пока
живут вперемешку с TS-кодом рендера, а не как отдельные данные.

### Состояние

`simState` в [public/modules/core/state.ts](public/modules/core/state.ts) —
глобальный `Proxy`-объект, отражающий текущего выбранного дрона из `drones`.
Это единственный источник истины для физики/UI на клиенте; мутация полей
`simState.*` — это и есть основной способ поменять что-либо в симуляции.
Помимо этого в нескольких модулях используется `window as any` для
протаскивания глобалов (`THREE`, `fengari`) — это осознанный компромисс ради
совместимости с Lua/Python-раннерами, но не образец для нового кода.

### Сервер (`server/`, точка входа `server.ts`)

Express-сервер раздаёт статику (в проде — `dist/public`) и держит несколько
API-роутов:

- `server/python-runtime.ts` — запускает **присланный от клиента Python-код**
  локальным процессом (`child_process.spawn`) через обёртку, подставляющую
  параметры подключения к `pioneer_sdk`. Это осознанная фича симулятора
  (запуск «настоящего» Python), но она означает, что сервер выполняет
  произвольный код по запросу. Прод-деплой публично доступен из интернета
  без авторизации (ученики заходят по домену), поэтому в `server.ts` есть базовые
  ограничения на этот случай — их нужно настроить переменными окружения:
  - `CORS_ORIGIN` — список разрешённых origin через запятую
    (например, `CORS_ORIGIN=https://sim.example.ru`). Без неё CORS открыт
    для всех origin — удобно для локальной разработки, но **обязательно
    выставляйте эту переменную в проде**.
  - `RATE_LIMIT_MAX` / `RATE_LIMIT_WINDOW_MS` — лимит запросов к `/api/*`
    на один IP (по умолчанию 30 запросов / 60 секунд).
  - `TRUST_PROXY_HOPS` — если сервер стоит за реверс-прокси (nginx и т.п.),
    выставьте число хопов до реального клиента, иначе rate limit будет
    считать всех пользователей за прокси одним IP.
  - `PYTHON_RUNTIME_MAX_CONCURRENT` — сколько локальных Python-раннеров
    может выполняться одновременно на сервере (по умолчанию 20).
  - `PYTHON_RUNTIME_MAX_SCRIPT_LENGTH` — максимальный размер присланного
    скрипта в символах (по умолчанию 200 000).
  - `PYTHON_RUNTIME_CPU_LIMIT_SECONDS` / `PYTHON_RUNTIME_MEMORY_LIMIT_KB` —
    лимиты `ulimit` (CPU-время и виртуальная память) для каждого запущенного
    процесса на Linux/macOS; на Windows не применяются.

  Это снижает ущерб от одного скрипта/IP, но **не является полноценной
  песочницей** — процесс всё ещё выполняется с правами пользователя,
  запустившего Node, без изоляции сети/файловой системы. Следующий шаг —
  запуск каждого сеанса в контейнере (Docker) с `--network=none` и лимитами
  ресурсов; на момент написания сервер работает на Linux без Docker.
- `server/external-python-bridge.ts` — событийный мост для внешнего Python,
  запущенного пользователем отдельно (не из браузера).
- `server/mavlink-bridge.ts` — мост к реальному MAVLink/дрону по UDP.
- `server/pioneer-connection.ts` — общие типы конфигурации подключения.

### Внешний Python (`python_bridge/`)

Хук для Python пользователя (IDLE, PyCharm, консоль): `python tools/install_idle_bridge.py`
кладёт `pioneer_browser_bridge_*.py` и `.pth`-файл в user site-packages, после чего
`pioneer_sdk.Pioneer`/`Camera` при создании выбирают, куда слать команды:

- `ip` — адрес сайта (`https://simulator.sakoryagin.ru`) — всё идёт по HTTPS в этот
  симулятор, включая кадры камеры. Работает через NAT/прокси; нужен только открытый
  симулятор с нажатой у дрона кнопкой «Разрешить внешние команды».
- переменная `PIONEER_BROWSER_BRIDGE_URL` — то же, на этот адрес.
- на этом компьютере запущен симулятор (localhost:3000/3001/1234) — в него (режим IDLE).
- иначе — настоящий `pioneer_sdk`: реальный дрон работает и с установленным хуком.

Без хука до сервера можно достучаться и напрямую по MAVLink
(`Pioneer(ip='simulator.sakoryagin.ru', mavlink_port=8001)`, UDP 8001), но камера
Pioneer через интернет так не работает: кадры идут по UDP на порт клиента, и домашний
роутер их отбрасывает. Для камеры нужен HTTPS-режим выше.

## Известные ограничения (для тех, кто планирует поддержку)

- `tsconfig.json` использует `strict`, но `eslint.config.mjs` отключает
  `no-explicit-any`/`no-unused-vars` — линт не ловит потерю типов и мёртвый
  код, полагайтесь на `type-check` и ревью.
- `/api/python-runtime/run` выполняет произвольный код от клиента. На проде
  (публичный домен, без авторизации) обязательно настройте `CORS_ORIGIN` и
  остальные переменные из раздела «Сервер» выше — без них сервер защищён
  только базовыми лимитами, а не полноценной песочницей.
