# Debug Session: simulator-no-command

Status: [OPEN]

## Симптом

- Симулятор не реагирует ни на `192.168.4.1`, ни на `127.0.0.1`.
- Python-скрипт с `Pioneer` и `Camera` не вызывает ни полёт, ни получение кадра.

## Ожидаемое поведение

- Команды `arm`, `takeoff`, `go_to_local_point`, `land`, `disarm` доходят до симулятора.
- `Camera.get_cv_frame()` получает кадры из web-simulator bridge.

## Гипотезы

1. События из Python runtime вообще не доходят до `/api/external-python-bridge/event`.
2. События доходят до сервера, но браузерный poller не подхватывает их из `/api/external-python-bridge/events`.
3. События доходят до браузера, но `resolveExternalDroneId()` не связывает их с дроном и команды не применяются.
4. Состояние камеры/автопилота пишется в bridge-state, но читается по другому ключу и потому Python видит пустой результат.
5. После последней правки серверный key lookup сломал совместимость и теперь не находится даже loopback-сценарий.

## План

1. Поднять debug server и собрать runtime-логи с Python, server и browser.
2. Воспроизвести сценарий вашим скриптом.
3. Подтвердить или опровергнуть гипотезы по логам.
4. Внести минимальный фикс только после подтверждения причины.
5. Повторно воспроизвести и сравнить pre-fix/post-fix.

## Проверка гипотез

| ID | Гипотеза | Статус | Доказательство |
|----|----------|--------|----------------|
| A | События из Python runtime вообще не доходят до `/api/external-python-bridge/event` | Подтверждена частично | В `.dbg/trae-debug-log-simulator-no-command.ndjson` есть только browser poll без Python-событий; Python-команда не доходила до первого bridge-event. |
| B | События доходят до сервера, но браузерный poller не подхватывает их из `/api/external-python-bridge/events` | Отклонена для текущего сбоя | Browser poll стабильно работает и читает очередь, но получает `eventCount: 0`, потому что Python ничего не публикует. |
| C | События доходят до браузера, но `resolveExternalDroneId()` не связывает их с дроном | Не проверялась до конца | До этой стадии выполнение не доходило, потому что Python зависает раньше публикации событий. |
| D | Состояние камеры/автопилота пишется в bridge-state, но читается по другому ключу | Не проверялась до конца | До state-sync выполнение не доходило, так как импорт/patch зависает раньше вызовов SDK. |
| E | Последняя правка серверного key lookup сломала совместимость | Отклонена как текущая первопричина | `faulthandler` показал зависание внутри `pioneer_browser_bridge_bootstrap`/`pioneer_browser_bridge_runtime`, а не в server lookup. |

## Подтверждённая причина

- `import pioneer_sdk` зависает из-за рекурсивного срабатывания `pioneer_browser_bridge_bootstrap`.
- Во время `patch_pioneer_sdk_module()` вызывается `_report_debug()`, тот делает `urllib.request.urlopen(...)`, внутри идут дополнительные импорты стандартной библиотеки, а глобально переопределённый `__import__` снова вызывает `_patch_if_needed()`.
- Из-за отсутствия защиты от реэнтрантности bootstrap зацикливается и до реальных вызовов `Pioneer.arm()/takeoff()` выполнение не доходит.
