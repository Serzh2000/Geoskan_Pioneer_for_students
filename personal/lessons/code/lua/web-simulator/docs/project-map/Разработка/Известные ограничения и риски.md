# Известные ограничения и риски

Для тех, кто планирует поддержку/деплой проекта.

## Типизация и линт разошлись

`tsconfig.json` использует `strict`, но `eslint.config.mjs` отключает
`no-explicit-any`/`no-unused-vars` — линт не ловит потерю типов и мёртвый код.
Полагайтесь на `npm run type-check` и ревью, а не только на `npm run lint`.

## Сервер выполняет произвольный код

`/api/python-runtime/run` ([[Python Runtime]]) выполняет присланный клиентом
Python-код локальным процессом. На проде (публичный домен, без авторизации —
ученики заходят по прямой ссылке) это означает выполнение произвольного кода
по запросу без изоляции сети/файловой системы. Обязательно настраивайте:

- `CORS_ORIGIN`
- `RATE_LIMIT_MAX` / `RATE_LIMIT_WINDOW_MS`
- `TRUST_PROXY_HOPS` (если за реверс-прокси)
- `PYTHON_RUNTIME_MAX_CONCURRENT`
- `PYTHON_RUNTIME_MAX_SCRIPT_LENGTH`
- `PYTHON_RUNTIME_CPU_LIMIT_SECONDS` / `PYTHON_RUNTIME_MEMORY_LIMIT_KB`

Это снижает ущерб от одного скрипта/IP, но **не полноценная песочница**.
Следующий шаг — Docker-контейнер с `--network=none` и лимитами ресурсов на
каждый сеанс; на момент написания README сервер работает на Linux без Docker.
Подробности — [[Python Runtime]].

## `window as any` для глобалов

Несколько модулей клиента протаскивают `THREE`/`fengari` через
`window as any` ради совместимости с раннерами [[Lua]]/[[Python]]. Осознанный
компромисс, не образец для нового кода. См.
[[Состояние (simState)]].

## Контент уроков смешан с кодом рендера

`ui/mission-guide/` — контент уроков (`lessons/`, `curriculum/`) живёт
вперемешку с TS-кодом рендера, а не как отдельные данные. См.
[[Mission Guide]].

## Крупные файлы

`docs/refactor-300-plus-audit.md` (в корне репо) — список файлов длиннее 300
строк и план их декомпозиции; вести его в актуальном состоянии при
рефакторинге крупных модулей.
