**Предлагаемая архитектура**
- `Вводная страница`: первая точка входа после авторизации или открытия проекта; содержит описание практикума, цели, структуру, правила прохождения, форматы уроков, критерии завершения и ожидаемый результат.
- `Каталог/маршрут курса`: обзор всех уроков в виде дорожной карты; видно, что пройдено, что доступно, что заблокировано.
- `Отдельная страница урока`: каждый урок получает собственный route/state и единый шаблон:
  - теоретический блок;
  - практический блок;
  - статус проверки;
  - кнопки `Назад` / `Далее`;
  - индикатор прогресса по курсу.
- `Слой прогресса`: хранит статус уроков, результаты проверок, unlock-логику и точку возврата пользователя.
- `Слой контента`: теория, задания, критерии успеха, подсказки, диагностические сообщения, решение-образец.
- `Слой оценки`: использует существующую механику проверки практики и расширяется до формального `lesson completion contract`.

**Структура урока**
- `Hero`: номер, название, цель, ожидаемый результат.
- `Теория`: 2–4 смысловых секции с короткими абзацами, схемами, API-фокусом и ключевыми выводами.
- `Практика`: одно основное задание и при необходимости 1–2 подзадачи.
- `Проверка`: автоматическая валидация, список ошибок, рекомендации по исправлению.
- `Финальный статус`: `не начат` / `в процессе` / `выполнен`.
- `Переход`: `Далее` активируется только при полном успешном прохождении.

**Механизм блокировки**
- У каждого урока вводим состояния:
  - `locked`
  - `available`
  - `in_progress`
  - `completed`
- Правило открытия:
  - урок `N+1` открывается только если урок `N` имеет `completed = true`;
  - если в уроке несколько практических задач, все должны быть закрыты успешно;
  - кнопка `Далее` не просто не ведет дальше, а визуально объясняет причину блокировки.
- Прогресс сохраняем локально на первом этапе:
  - `localStorage` или существующий клиентский state-store;
  - позже можно вынести в серверный профиль пользователя.
- На вводной и в каталоге показываем:
  - процент прохождения;
  - текущий урок;
  - ближайший заблокированный урок.

**Контентная модель курса**
- Предлагаю разбить курс на 4 смысловых блока по `10–15` уроков:
- `Блок 1. Введение и среда`
  - вводная страница;
  - знакомство с интерфейсом;
  - базовые команды;
  - запуск первого сценария.
- `Блок 2. Базовое управление`
  - `PREFLIGHT`, `TAKEOFF`, `LANDING`;
  - таймеры;
  - FSM-мышление;
  - `callback(event)`.
- `Блок 3. Навигация и сценарии`
  - `goToLocalPoint`;
  - ожидание `TAKEOFF_COMPLETE`;
  - `POINT_REACHED`;
  - последовательные миссии.
- `Блок 4. Практические миссии`
  - составные задания;
  - поиск и исправление ошибок;
  - итоговая миссия;
  - финальное закрепление.
- Для каждого урока фиксируем:
  - `learning objective`;
  - `theory scope`;
  - `practice task`;
  - `auto-check criteria`;
  - `unlock condition`;
  - `common mistakes`.
